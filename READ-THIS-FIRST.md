# Ultra Cast v3 — player rebuild, exact files

**Do not re-implement, re-derive, or "improve" anything in this folder. Copy the files in,
overwriting what is there. That is the whole job.**

Every file here is byte-identical to the build that was tested on a Fire TV Stick, a phone and
BlueStacks. The only edited value is the app version, set to **3.0.3** — one up from the repo's 3.0.2.

Several of these fixes are one-character-sensitive. For example a subtitle prop that reads
`activeText >= 0 ? activeText : -1` instead of `activeText === -2 ? undefined : ...` silently stops
subtitles turning off, with no error anywhere. Retyping from a description will reintroduce exactly
these bugs; they took several device test rounds to find.

---

## How to apply

1. Copy every file in this folder into the repo at the same path, overwriting existing files.
2. Install the three new dependencies (they are already listed in the `package.json` here):

```
npx expo install expo-font @expo-google-fonts/archivo @expo-google-fonts/chivo
```

3. Nothing else. No code changes, no refactoring, no renaming.

Do **not** copy an `android/` folder — it is generated by `expo prebuild` and is not part of this.

## Why each fix exists

Kept short so nobody "tidies up" something load-bearing.

**Fire TV remote keys never worked.** The player screens already handled media keys through
`TVEventHandler` — but that only exists in the `react-native-tvos` fork, so
`require("react-native").TVEventHandler` was always `undefined` and the handler bailed on its first
line. The new native module forwards keys from `MainActivity.dispatchKeyEvent` to JS;
`client/lib/tv-event-handler.ts` presents the same API the screens already expected. D-pad keys are
reported but **never consumed**, so focus traversal is unaffected.

**Subtitles showed "Off" while subtitles were on screen.** Two separate causes.
`video-player.tsx`'s `subtitleTrack` getter returned `null` unconditionally, and `_textTrackId`
started `undefined`, so VLC picked its own default. Separately, VLC reports the track *lists* on load
but never which one is selected, and exposes no getter — so claiming "Off" was a guess. The panel now
says "Stream default" until the user chooses, which is true.

**Subtitles could not be turned off** without first switching one on. `VlcPlayerScreen` rendered
`textTrack={activeText >= 0 ? activeText : -1}` — "untouched" (-2) and "off" (-1) both rendered as
`-1`, so pressing Off changed no prop value, React sent nothing, and VLC kept its subtitles. Untouched
now renders as `undefined`.

**Aspect ratio did nothing on the VLC player.** `resizeMode` is not a prop the VLC Android view
supports — it exists only in the library's JS propTypes and is dropped before native. Only
`videoAspectRatio` and `autoAspectRatio` work, and the former is ignored while the latter is true.

**Aspect ratio crashed on Fire TV (expo player).** The `VideoView` was keyed on the aspect mode, so
changing it rebuilt the native video surface mid-playback. `contentFit` is a live prop, so no remount
is needed. **Do not reintroduce that key.**

**Seeking by remote did nothing.** `PlayerScreen` declared `seekBarFocusedRef` but never assigned it,
so the seek branch could never run; and the seek bar was deliberately a plain `View` to keep the D-pad
away from it. It is now focusable and traps left/right on itself, so only up/down leave the bar.

**Seeking stuttered.** Every key press committed a real seek, so the player re-buffered between
presses. Presses now move a target and the bar; the seek commits 600ms after the last press. The
600ms/900ms timings are tuned for a TV remote driving a Fire Stick over HDMI-CEC, which repeats slowly
and irregularly — tighter values bring the stutter back.

**Controls auto-hid with a panel open**, and **focus vanished when a panel closed** (the focused view
was unmounted with nothing taking its place).

**One shared control bar.** The three player screens had each grown their own buttons, track panels
and seek bars, which is why they looked different and behaved differently. Each screen's local
components are now thin adapters over `client/components/player/*`.

## Worth knowing

- The native module means **this cannot run in Expo Go** — it needs a real build. That was already
  true of this app (VLC).
- The fonts add about 1.5MB to the APK and load **non-blocking** — the app renders immediately in the
  system font and swaps when they arrive. Do not make startup wait on them.
- `playerLabels.ts` holds every control's wording. "Audio" is currently labelled **"Language"**. That
  is wrong when a title carries the same language twice in different formats (English 5.1 and English
  stereo); if that shows up in the library, change that one line back to `"Audio"`.
- There are 42 pre-existing TypeScript errors in `client/` that have nothing to do with this work
  (47 before it — this reduced the count). The number should not go **up**.
