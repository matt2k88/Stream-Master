# Database Migrations

SQL migrations the user must run in the Supabase SQL Editor live under
`migrations/`. Run any not-yet-applied ones in order. Each is written to
degrade gracefully until run (endpoints return `[]`, defaults kick in).

- `001_continue_watching.sql` — adds `current_time`, `duration`, `is_completed`, `series_id`, `season_num`, `episode_num` to `recently_watched`.
- `002_content_reports.sql` — creates `content_reports` (id, profile_id, stream_id, stream_name, stream_type, reason, other_text, created_at).
- `003_category_prefs.sql` — creates `category_prefs` (id, profile_id, type, order_ids text[], hidden_ids text[], updated_at) with unique (profile_id, type). Per-profile category organise prefs (order + hidden) for Live/Movies/Series so they sync across devices.
- `004_app_theme.sql` — creates singleton `app_theme` (id=1, theme_key text, updated_at) with default `theme_key='default'`. Admin sets `theme_key` to one of `default|halloween|bonfire|christmas|valentines|newyear`.
- `007_series_progress.sql` — adds nullable `series_last_modified text` and `series_total_episodes integer` to `recently_watched`. Snapshots on each play so the dashboard can detect "new episodes uploaded" without a per-row API call.
- `008_series_final_episode.sql` — adds nullable `series_final_season int` and `series_final_episode int` to `recently_watched`. Snapshot of highest-season → highest-episode at play time. Dashboard marks a series WATCHED only when the user has a completed entry matching this final episode. Combined with 007, new uploads flip the series back to CONTINUE WATCHING + NEW EPISODES.
- `009_football.sql` — creates `football_prefs` (profile_id pk, league_id int nullable, corner text with CHECK on 6 corner keys, enabled bool default true, updated_at) and `football_scores` (fixture_id bigint pk, league/team fields, home_goals/away_goals, status_short, elapsed, finished_at nullable, updated_at). Until run, the poller logs "table not found" and prefs do not persist.
- `012_football_goal_events.sql` — adds nullable `last_goal_player`, `last_goal_team`, `last_goal_minute`, `last_goal_at` to `football_scores`. Poller writes the most-recent goal scorer (fetched from `/fixtures/events` only when a fixture's score increases). Optional — only the scorer name needs this; the score cache and client GOAL flash work without it.
- `013_football_global.sql` — creates singleton `football_global` (id=1 with CHECK, `enabled` bool default true, updated_at) + default row. Admin flips `enabled` to globally enable/disable the **whole** football feature. Until run, server/client default the flag to true.
- `014_football_visible_lines.sql` — adds `visible_lines int default 5` (CHECK 1–6) to `football_prefs`. Per-profile scoreline count for the tracker. Written via a separate guarded update so a not-yet-run migration never blocks core pref saves; defaults to 5.
- `015_football_fixtures.sql` — creates `football_fixtures` (fixture_id bigint pk, league/team fields, home_logo/away_logo, kickoff timestamptz, date_key text YYYY-MM-DD, status_short, updated_at). Server-maintained cache of upcoming fixtures (next 7 days, curated leagues, refreshed ~once/day). Read by Football Centre "Upcoming". Until run, the endpoint returns `[]`.
- `016_football_fixture_channels.sql` — creates `football_fixture_channels` (fixture_id bigint **PK + FK→football_fixtures(fixture_id) on delete cascade**, channel_name text, stream_id text nullable, updated_at). One row per fixture mapping it to the live TV channel (populated externally). Read via `GET /api/football/centre/channels`. Channel rows are removed automatically when their fixture is purged (FK cascade). Until run, the endpoint returns `[]`.
- `017_football_score_logos.sql` — adds nullable `home_logo`, `away_logo` to `football_scores` so Live Now cards show team badges. Poller writes `teams.home.logo`/`teams.away.logo`; if columns don't exist it retries the upsert with logos stripped so the score cache never breaks. Until run, Live cards just show no badge.
- `018_profile_favourite_team.sql` — creates `profile_favourite_team` (profile_id uuid PK, team_id int, team_data jsonb `{id,name,code,logo}`, created_at, updated_at). Per-profile favourite football team in the MAIN db, read/written via `GET`/`PUT /api/football/favourite-team`. The team picker searches api-football via `GET /api/football/teams?search=` (min 3 chars). **After running this migration, trigger the one-time bulk import** (`POST /api/football/favourite-team/import`) to copy each account's existing favourite from the lifetime db `user_favorite_teams` (keyed by iptv_username) onto every profile under that `account_username`. The import is idempotent (skips profiles that already have a favourite) so it is safe to re-run; profiles created afterwards start with no favourite. Until this migration is run, the favourite-team endpoints return `null`/persist nothing and the rest of the Football screen keeps working.
- `019_match_reminders.sql` — adds `reminders_enabled boolean not null default false` to `profile_favourite_team`. Per-profile Match Notifications on/off, read/written via `GET`/`PUT /api/football/match-reminders` so the toggle follows the profile across devices. The per-fixture "already shown" dedupe state stays device-local (AsyncStorage). The toggle is only usable once a favourite team is set, so the row always exists before the flag is written. Guest profiles keep the flag device-local. Until run, the GET returns `{ enabled: false }` and the PUT is a no-op.
- `020_player_hw_decode.sql` — adds `player_hw_decode text not null default 'auto'` (CHECK in `auto|on|off`) to `profiles`. Per-profile VLC hardware-decoding override, read/written via `GET`/`PUT /api/profiles/:id` alongside `player_vod`/`player_live`. `auto` keeps existing behaviour, `off` forces software decoding for devices with a flaky hardware decoder (green/garbled frames, stutter, no audio). Only affects the VLC engine; Expo ignores it. Guest profiles keep the value device-local (AsyncStorage). Run this alongside the other not-yet-applied migrations: until it is applied the column does not exist, so saving Video Decoding on a non-guest profile fails the PUT (same as the engine prefs before `005`); playback still defaults to `auto` everywhere.
- `021_advert_orientation.sql` — adds nullable `orientation text` (CHECK `landscape|portrait` or NULL) to `adverts`. Lets the home advert carousel show different art per orientation: `'landscape'` rows only appear in the TV/landscape banner, `'portrait'` rows only in the mobile portrait banner, and NULL rows appear in both. The `GET /api/adverts` route retries its select without the column if it is absent, so before this migration is applied every ad shows in both orientations.
- `022_advert_category.sql` — adds nullable `category text` (CHECK one of: `featured_event`, `featured_movie`, `featured_series`, `upcoming_event`, `new_release`, `coming_soon`, `exclusive`, `featured_advert` or NULL) to `adverts`. Displayed as a coloured icon + label badge above the advert image in the carousel. NULL rows show no badge. The `GET /api/adverts` route retries without `category` if the column is absent, so the carousel keeps working before this migration is run.
- `023_private_viewing.sql` — adds `private_viewing boolean not null default false` to `profiles`. When enabled by the user from the Settings screen, the `POST /api/recently-watched` server route skips inserting any watch history rows for that profile, so nothing is stored in `recently_watched` while the mode is active. Client-side, `upsertLocal` also silently no-ops so the in-memory Continue Watching list is not updated. Toggle is per-profile and persisted via `PUT /api/profiles/:id`. Until this migration is run, the column does not exist and the PUT will fail silently (the `private_viewing` patch is dropped on the floor by Supabase); all watch history tracking continues as normal.

- `024_player_buffer.sql` — adds `player_buffer_ms integer not null default 3000` to `profiles`. Per-profile network pre-buffer setting (1 500 / 3 000 / 5 000 / 10 000 / 30 000 ms) applied to both the VLC (`--network-caching` + `--file-caching`) and Expo/ExoPlayer (`bufferOptions`) engines. Read/written via `GET`/`PUT /api/profiles/:id`. Guest profiles keep the value device-local (AsyncStorage). Until run, `player_buffer_ms` is absent from the column list so the PUT drops the field silently; all players continue to use the 3 000 ms hard-coded default.

- `025_ultra_tube.sql` — creates `ultra_tube_access` (username → ultra_tube_username + ultra_tube_password, unique on lowercase ultracast username) and `ultra_tube_config` (id=1 row: apk_url, downloader_code, show_badge). Seeded with defaults. Used by `/api/ultra-tube/config` and `/api/ultra-tube/check`. Until run, both endpoints fall back to hardcoded defaults; the access-check will always return `{ hasAccess: false }` (PGRST116 is ignored silently).

- `026_avatar_image.sql` — adds nullable `avatar_image text` to `profiles`. Stores a base64-encoded 320×320 JPEG uploaded via the QR-code photo flow in the Edit Profile screen. When set, the photo overrides the icon+colour avatar everywhere in the app (profile picker, home bar, dropdown). Until run, the column does not exist and avatar uploads fail silently (the PUT drops `avatar_image`); icon/colour avatars continue to work normally.

- `027_music_badges.sql` — adds `show_music_badge boolean default true` and `show_music_beta_badge boolean default true` to `app_theme`. Admin flips either to `false` in Supabase to hide the NEW badge on the Music Player menu item or the BETA badge inside the Music Player screen respectively. Both endpoints fall back to `true` until this migration is run so both badges show immediately on deploy.

- `028_music_playlists.sql` — creates `music_playlists` (id uuid pk, profile_id → profiles, name, is_liked_songs bool, created_at, updated_at) and `music_playlist_tracks` (id uuid pk, playlist_id → music_playlists, title, artist, album, duration_sec int, thumbnail, search_key, position int, added_at). A unique index on `(playlist_id, search_key)` prevents duplicate tracks. The playlist API endpoints (`GET/POST/PUT/DELETE /api/music/playlists`, `GET/POST/DELETE /api/music/playlists/:id/tracks`) auto-create a "Liked Songs" playlist on first `GET` for each profile. Until run, all endpoints return `[]` / `503` gracefully and the UI shows an empty playlists section rather than erroring.

- `031_content_ratings.sql` — creates `content_ratings` (id bigserial pk, content_type text CHECK movie|tv, tmdb_id bigint, certification text, age_int smallint, source text, updated_at, UNIQUE on content_type+tmdb_id). Server-side cache of TMDB age certificates (GB/BBFC first, US/MPAA fallback). Populated lazily when a user opens MovieInfoScreen or SeriesDetailScreen (exact tmdb_id from VodInfo → one TMDB cert API call) and in bulk via a background job that fires after each DataContext sync (name-based TMDB search, ~300ms/item). The `GET /api/content-ratings?tmdb_id&content_type` and `POST /api/ratings/enrich` routes return 200 gracefully (null / 0 queued) until this migration is run, so all existing screens keep working unchanged. Run this before expecting age badges to appear.

- `032_stream_ratings.sql` — creates `stream_ratings` (stream_id integer + content_type text PRIMARY KEY, certification text, age_int smallint, tmdb_id bigint nullable, source text, updated_at) **and disables Row Level Security** (`ALTER TABLE stream_ratings DISABLE ROW LEVEL SECURITY`). Keyed by stream_id so parental controls can filter the full library in O(1) per item. **If you ran an earlier version of this migration that did not include the RLS line, run it manually in the Supabase SQL editor:** `ALTER TABLE stream_ratings DISABLE ROW LEVEL SECURITY;` — without it all inserts silently fail. Populated entirely server-side: after every sync DataContext POSTs all stream names to `POST /api/stream-ratings/enrich`; the server queues them and processes via TMDB name search at ~250ms/item in the background (no client-side `getVodInfo` calls needed). Progress is readable at `GET /api/stream-ratings/status`. DataContext loads all stored ratings on sync via `GET /api/stream-ratings?content_type=movie|tv` and exposes them as a `Map<stream_id, {certification, age_int}>` for instant badge display and future parental-control filtering. Until this migration is run (with RLS disabled), endpoints return `[]` gracefully and all screens keep working with no badges shown.

> **Note on numbering**: gaps (005–006, 010–011, 026–027, 029–030) were intentionally skipped during earlier development; ordering above reflects application order.
