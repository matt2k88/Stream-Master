# Database Migrations

SQL migrations the user must run in the Supabase SQL Editor live under
`migrations/`. Run any not-yet-applied ones in order. Each is written to
degrade gracefully until run (endpoints return `[]`, defaults kick in).

- `001_continue_watching.sql` — adds `current_time`, `duration`, `is_completed`, `series_id`, `season_num`, `episode_num` to `recently_watched`.
- `002_content_reports.sql` — creates `content_reports` (id, profile_id, stream_id, stream_name, stream_type, reason, other_text, created_at).
- `003_category_prefs.sql` — creates `category_prefs` (id, profile_id, type, order_ids text[], hidden_ids text[], updated_at) with unique (profile_id, type). Per-profile category organise prefs (order + hidden) for Live/Movies/Series so they sync across devices.
- `004_app_theme.sql` — creates singleton `app_theme` (id=1, theme_key text, updated_at) with default `theme_key='default'`. Admin sets `theme_key` to one of `default|halloween|bonfire|christmas|valentines|newyear`.
- `007_series_progress.sql` — adds nullable `series_last_modified text` and `series_total_episodes integer` to `recently_watched`. Snapshots on each play so the dashboard can detect "new episodes uploaded" without a per-row API call.
- `008_series_final_episode.sql` — adds nullable `series_final_season int` and `series_final_episode int` to `recently_watched`. Snapshot of highest-season → highest-episode at play time. Dashboard marks a series WATCHED only when the user has a completed entry matching this final episode. Combined with 007, new uploads flip the series back to CONTINUE WATCHING + NEW EPISODES.
- `009_football.sql` — creates `football_prefs` (profile_id pk, league_id int nullable, corner text with CHECK on 6 corner keys, enabled bool default true, updated_at) and `football_scores` (fixture_id bigint pk, league/team fields, home_goals/away_goals, status_short, elapsed, finished_at nullable, updated_at). Until run, the poller logs "table not found" and prefs do not persist.
- `012_football_goal_events.sql` — adds nullable `last_goal_player`, `last_goal_team`, `last_goal_minute`, `last_goal_at` to `football_scores`. Poller writes the most-recent goal scorer (fetched from `/fixtures/events` only when a fixture's score increases). Optional — only the scorer name needs this; the score cache and client GOAL flash work without it.
- `013_football_global.sql` — creates singleton `football_global` (id=1 with CHECK, `enabled` bool default true, updated_at) + default row. Admin flips `enabled` to globally enable/disable the **whole** football feature. Until run, server/client default the flag to true.
- `014_football_visible_lines.sql` — adds `visible_lines int default 5` (CHECK 1–6) to `football_prefs`. Per-profile scoreline count for the tracker. Written via a separate guarded update so a not-yet-run migration never blocks core pref saves; defaults to 5.
- `015_football_fixtures.sql` — creates `football_fixtures` (fixture_id bigint pk, league/team fields, home_logo/away_logo, kickoff timestamptz, date_key text YYYY-MM-DD, status_short, updated_at). Server-maintained cache of upcoming fixtures (next 7 days, curated leagues, refreshed ~once/day). Read by Football Centre "Upcoming". Until run, the endpoint returns `[]`.
- `016_football_fixture_channels.sql` — creates `football_fixture_channels` (fixture_id bigint **PK + FK→football_fixtures(fixture_id) on delete cascade**, channel_name text, stream_id text nullable, updated_at). One row per fixture mapping it to the live TV channel (populated externally). Read via `GET /api/football/centre/channels`. Channel rows are removed automatically when their fixture is purged (FK cascade). Until run, the endpoint returns `[]`.
- `017_football_score_logos.sql` — adds nullable `home_logo`, `away_logo` to `football_scores` so Live Now cards show team badges. Poller writes `teams.home.logo`/`teams.away.logo`; if columns don't exist it retries the upsert with logos stripped so the score cache never breaks. Until run, Live cards just show no badge.
